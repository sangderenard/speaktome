## Main finding

The retention boundary is an evaluated **exact context**, not merely a FluxNode. Keep distribution observations tied to existing node IDs, exact effective input tokens, and evaluation/formation provenance. Nodes and their anchor-relative contexts can change; a scalar stored on a newly grown child currently describes the parent's selection or a backward suffix score, not the child's next-token distribution. Evaluating terminal children is necessary to measure all parent-child and sibling distances.

## Minimal proposed retention contract

Add optional observation retention at existing model-output boundaries, before masking, narrowing or top-k. This is an implementation proposal; this documentation change implements none of it.

- Owner: existing graph/session owns immutable evaluation records; nodes refer to their observations. Lookahead emits equivalent observations attached to its existing run/parent/path provenance. This is a measurement store, not another graph, allocator, path engine or topology authority.
- Identity: model/checkpoint and tokenizer/vocabulary-order fingerprint, backend/device/precision, exact effective context and mask, raw-model temperature convention, run/evaluation ID, existing node/path IDs, anchor ID/tick, and transform provenance. Multiple evaluations of one node remain separate. Shared storage is allowed only for identical verified context/model contracts; never merge nodes because distributions are close.
- Canonical numeric storage: one full unmasked last-position logit vector plus normalization metadata suffices to derive full probabilities/log-probabilities and margin. Alternatively retain one full normalized log-probability vector plus separately measured raw top-logit margin; raw absolute logits then are not retained. Decide one representation explicitly. Avoid retaining both probabilities and log-probabilities unnecessarily. Optional raw+normalized dual storage doubles the ledger.
- Storage must own only a V-element row, not a view keeping an entire batch/sequence tensor alive. It must not keep autograd history alive. Follow AbstractTensor interfaces; do not insert concrete-backend logic into consumers. Verify release/alias behavior on supported backends before asserting memory savings.
- Measurements and provenance are immutable relative to reroot/burn. Missing terminal distributions are explicitly missing until evaluated. A capacity failure yields an incomplete-run receipt, not silent top-k replacement or adaptive budget changes.
- No new causal Edge for behavioral similarity. First deliver pairwise measurements referencing existing observations. Forward edges retain transition evidence; backward edges retain searched-score evidence; candidate behavioral relationships remain distinctly labeled analysis results.

## First fixed experiment

Proposed specification for later implementation and execution:

- Existing GPT-2 engine, exact checkpoint/tokenizer revision resolved and recorded before starting; no unspecified latest model. Use its existing supported environment and tensor backend, inference/eval mode, fixed precision, temperature 1, deterministic top-k and declared tie ordering.
- Exact prompt: `The river flows toward`. Save token IDs as well as text and record BOS/EOS handling. This is an experimental choice, not an established project default.
- k=4 successors per evaluated context, depth d=3 new tokens. No trie, poetic reranker, no-repeat masking, auxin suppression, top-p/stddev or cross-growth in this controlled observation run. Do not change production defaults.
- Reuse FluxGraph forward creation/batched expansion and its existing multi-round behavior; do not use Lookahead's globally capped beam and describe it as full breadth. The [existing hot loop](https://github.com/sangderenard/speaktome/blob/8b1b144c8a973f7e9cc8f2fe6f5e272aaf24f9c6/speaktome/core/flux_graph.py#L4435-L4487) feeds new children back to existing expansion and documents exponential breadth and population stops. Fixed experiment driving is separate from changing the live pressure scheduler: no adaptive policy or physics edits.
- Expect 1+4+16+64=85 context observations, 84 forward edges and 21 sibling groups, assuming vocabulary >=4 and no early terminal/cap. Obtain P at all 64 depth-three leaves via observation-only evaluation; do not grow a fourth topology level. Generation alone evaluates only the 21 internal contexts. Record actual model rows and calls separately because batching changes calls, not contexts.
- If EOS or context/cap behavior changes the intended counts, report actual coverage and exclusion reasons. For this tiny prompt/depth choose a context limit that does not truncate and verify it from token IDs.

Metrics: full-vocabulary entropy in nats; untempered largest-minus-second-largest logit margin; JS divergence and sqrt(JS) distance for all 84 parent-child pairs and 126 sibling pairs; selected-token transition log-probability from the parent's raw distribution as a separate value. Use natural logs consistently and stable log-space mixture calculations, with zero-probability contributions defined by their limiting value.

For reconvergence, inspect same-depth, textually distinct context pairs and follow their explicitly identified ancestral branch pairs across depths. Report distance contraction as a trajectory, absolute distance and ratio where initial distance is nonzero, alongside token edit/tree distance. Label candidates only; no semantic equivalence claims, node mergers or causality inferred from layout. Distinct-context checks exclude identical token contexts and truncation collisions. Retain full pairwise values so any later threshold is declared rather than chosen silently after inspecting results.

Exact full-vocabulary JS requires full vectors or an equivalent complete representation. Independently stored top-k lists plus tail mass do not provide it. A shared, explicitly defined partition permits a coarsened JS; top-k-union bins require each distribution's probabilities for every union token, which separate top-k summaries may not contain. Label any such result coarsened, never exact. This experiment uses full vectors.

## Memory ledger and bounded completion

For U distinct retained contexts, vocabulary V and b bytes/element, one owned dense plane costs U*V*b; two cost 2*U*V*b. At U=85, V=50,257, FP32: 17,087,380 bytes (about 16.30 MiB) per plane; dual raw-logit/normalized retention is about 32.59 MiB. These are payload estimates, not measured process/GPU usage; confirm actual V/dtype.

Ledger separately: persistent CPU vectors; optional GPU staging; token/context metadata and scalar metrics; temporary full logits and log-softmax (`B*T*V` each, potentially different dtypes); gathered rows and indexed copies/views; pairwise metric scratch; backward teacher-forced candidates if enabled in later work; model weights/activations and any model-internal cache; allocator reserved versus allocated bytes; export buffers/files. Do not retain all intermediate backward `[candidate,position,V]` planes for this first forward experiment.

Existing [chunk planning](https://github.com/sangderenard/speaktome/blob/8b1b144c8a973f7e9cc8f2fe6f5e272aaf24f9c6/speaktome/core/flux_graph.py#L4799-L4837) budgets elements, not actual bytes, and allows one oversized row. Existing CPU fallback is not proof that downstream mixed-device gathered rows are safe. Record any fallback; don't combine different numeric regimes unnoticed. No allocator flushing or chunk-policy changes proposed.

Completion: all declared observations/metrics present or explicitly missing with reason; frozen run manifest and distribution payloads exported; measured versus estimated memory separated; replay checks passed; no changes to DAG IDs/edges, creation evidence, pressure/reproduction, selection or model call order attributable to retention. Stop there. Adaptive exploration remains a separate design decision with the maintainer.
