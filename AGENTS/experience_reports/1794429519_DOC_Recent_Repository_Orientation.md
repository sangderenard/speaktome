## Addendum: native Nodus GPU and runtime coupling question

Read current uncommitted Nodus `include/opengl_gpu_row_tool.h`,
`include/kernel_opengl_runner.h`, `src/kernels/kernel_opengl.cpp`,
`src/headless/nodus_headless_abi.cpp`, `src/contract_port_canvas.cpp`,
`src/mem_backend_host.cpp`, and the November 7 service-backbone and November 10
contract-port audits. No build or runtime latency probe was run.

Nodus has same-process row/FIFO communication and a measured earlier Vulkan
device-local two-shader packet crossing. The new uncommitted native GL schedule
preflights borrowed buffers, preserves stage order, and applies explicit GL
memory barriers, but its success receipt records submission, not GPU completion.
The new GPU tool row currently accepts `LinkOnly`; `Execute` is held. Its
`tick()` is empty and protected native GL supervision is an admission callback,
not an installed protected process. Headless contract ports use bounded
loopback sockets polled around a completed canvas tick; no key-frame latency
or jitter bound has been measured. The backend tagged SHARED_MEM here is
filesystem-backed with a null map operation, so it is not evidence of a live
zero-copy cross-process state channel. The UDP router batches socket input for
services and has no GPU coupling contract. A key-frame-rate guarantee cannot
be claimed from these source interfaces alone.
